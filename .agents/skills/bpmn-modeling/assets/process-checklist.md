# Process checklist
- Label observed as-is, hypothetical as-is and proposed to-be explicitly.
- State goal, trigger, end outcomes and business owner if known.
- Give each event/task/gateway/flow a unique ID.
- Keep sequence flows within a process; use messages across pools.
- Explain gateway conditions/defaults, merges and exception/cancellation outcomes.
- Link process tasks to requirements without claiming runtime evidence.
- For XML interchange add namespaces, references and BPMN DI where needed.
- Report XML parse, graph checks, XSD and engine checks separately.
- Do not claim a hand-drawn/Mermaid flowchart is BPMN XML.
- A graph reaching an end does not prove token semantics or execution behavior.
