# Editing techniques

## Pointers and information hierarchy
A pointer names material and the distinct condition for reaching it. Put the recognizable
trigger early. Collapse synonyms for one trigger; retain genuinely different task branches.
Remove identity repeated by the target when it adds no routing signal. If an essential
reference is missed, sharpen the pointer and test it before moving the entire reference inline.

Use three levels: in-file action; local reference near the action; disclosed reference for
a conditional branch. Co-locate definitions, rules and caveats. Flat reference is legitimate;
split by branch when different tasks need different material, not to hit a file-count target.
Compare context load for the agent with cognitive load for the human choosing workflows.
A short pointer still costs context; a separate unindexed document costs human discovery.

## Completion criteria
Clarity distinguishes done from not-done; demand states what must be accounted for.
For example, "check the change" is weaker than naming the affected invariants and reporting
PASS/FAIL/NOT_RUN evidence for each relevant check. Do not demand exhaustive unrelated work.
If an agent rushes toward later steps, first sharpen the current completion condition.
Split a sequence only when a real workflow boundary earns the cost; adding inline substeps
does not remove later instructions from context. No extra agent is required by this advice.

## Language and pruning
Use a precise familiar concept as a compact label when its meaning is shared; define
project-specific jargon before relying on it. Leading words can improve consistency but
do not prove token savings or activation reliability. Prefer positive target behavior;
retain explicit prohibitions when they express a material guardrail, paired with the action
the agent should take instead. Do not delete a necessary safety rule merely for containing a negation.

Check for stale facts, scattered caveats, duplicated meaning and guidance irrelevant to
current branches. Discoverable config is normally authoritative over a prose cache; retain
non-discoverable rationale. Before declaring an instruction a no-op, compare behavior
with/without it for the relevant model/task if feasible. Otherwise label it tentative.
Delete only within scope, and compare semantic consequences after pruning. Do not force
all shared guidance into one unavailable dependency; local repetition may preserve autonomy.
